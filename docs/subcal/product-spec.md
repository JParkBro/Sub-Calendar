# 제품 · 화면 정의

구독캘린더(SubCalendar)의 기능 범위, 계산 규칙, 화면 목록과 동작을 정의합니다. 디자인 시안(Stitch) 작업과 개발 모두 이 문서를 기준으로 합니다.

## 1. 제품 개요

| 항목 | 내용 |
|---|---|
| 한 줄 소개 | 매달 새는 구독료, 한눈에 보고 줄이기 |
| 대상 | 구독 서비스를 3개 이상 쓰는 20~40대 한국 사용자 |
| 플랫폼 | Android (iOS는 이후 검토) |
| 앱 표시 이름 | 구독캘린더 (가칭) |
| 패키지 | `jpark.bro.subcal` (dev: `jpark.bro.subcal.dev`) |
| 기본 원칙 | 로그인 없이 설치 즉시 사용. 데이터는 기기에만 저장 |

### 차별점

| 기능 | 왜 중요한가 |
|---|---|
| 무료체험 트래커 | 자동결제 전에 해지할 기회를 준다. 사용자가 가장 직접적으로 돈을 아끼는 순간 |
| 아낀 돈 | 해지한 구독이 "지금까지 얼마 아꼈는지"를 계속 보여줘 앱을 지울 이유를 없앤다 |
| 월급일 기준 집계 | "이번 달"을 1일이 아니라 월급일부터 셀 수 있다 |
| 파티 정산 | 공유 계정 1/N 계산과 정산 체크, 카톡 요청 문구 |

## 2. 구독 규칙 · 계산 규칙

모든 계산은 `core:domain`에 두고, 홈 · 목록 · 캘린더 · 통계 · 위젯 · 알림이 같은 함수를 씁니다. 결제 내역은 **저장하지 않고** 아래 규칙으로 만듭니다.

### 2-1. 구독 항목

| 구분 | 내용 |
|---|---|
| 필수 입력 | 이름, 금액, 통화, 결제 주기, 첫 결제일 |
| 선택 입력 | 요금제 이름, 카테고리, 결제 수단, 무료체험(시작일), 알림, 메모, 해지 페이지 주소, 아이콘 색, 사용 체크 켜기 |
| 상태 | `ACTIVE`(이용 중) · `PAUSED`(일시정지) · `CANCELLED`(해지) |
| 프리셋 | 서비스를 고르면 이름 · 카테고리 · 색 · 요금제 · 해지 주소를 채운다 (2-10) |

### 2-2. 결제 주기와 결제일

| 주기 | 저장 값 | 결제일 규칙 |
|---|---|---|
| 매월 | `MONTH`, 간격 1 | 첫 결제일의 "일"을 기준일로 매달. 그 날이 없는 달은 말일 (31일 → 4월 30일, 2월 28 · 29일). 다음 달은 원래 기준일로 돌아감 |
| 매년 | `YEAR`, 간격 1 | 첫 결제일의 월 · 일로 매년. 2월 29일은 평년에 2월 28일 |
| 매주 | `WEEK`, 간격 1 | 첫 결제일부터 7일마다 |
| 직접 | `DAY` · `WEEK` · `MONTH` · `YEAR` + 간격 2~99 | 위 규칙을 간격만큼 건너뜀 (예: 3개월마다). 월 · 년 간격도 말일 규칙을 따른다 |

- 결제일 n번째 = 첫 결제일 + (간격 × n). **앞 회차에서 계산하지 않고 항상 첫 결제일에서 계산**해서 말일 보정이 누적되지 않게 한다.
- 결제 시각은 다루지 않는다. 날짜만 쓴다.

### 2-3. 결제가 생기는 날 (발생 규칙)

어느 날짜에 실제로 결제가 있는지는 다음 순서로 거릅니다.

1. 2-2 규칙으로 나온 날짜일 것
2. 첫 결제일 이후일 것 (무료체험 기간에는 결제 없음)
3. 일시정지 기간(`pause.start_date` ~ `pause.end_date`, 양 끝 포함, 끝이 없으면 계속)에 들지 않을 것
4. 해지했다면 해지일(`cancelled_on`) **이전**일 것. 해지일 당일 결제는 없음
5. 금액은 그 날짜에 유효한 가격 (2-5)

### 2-4. 금액과 통화

| 항목 | 규칙 |
|---|---|
| 저장 | `amount_minor`(Long, 최소 단위) + `currency`(`KRW` · `USD`). KRW는 원, USD는 센트 |
| 표시 | KRW `13,900원`, USD `$9.99`. 합계 · 통계는 원화로 환산해서 보여줌 |
| 환율 | 설정의 "달러 환율"(기본 1,400원, 사용자가 수정). 환산 = `round(센트 × 환율 / 100)`, 원 단위 반올림. 자동 환율은 범위 밖 (서버 · 외부 API 없음) |
| 합산 | 항상 원화 Long으로 바꾼 뒤 더한다. 표시 직전에만 포맷 |

### 2-5. 가격 변경

- 금액을 바꿀 때 "언제부터 적용할까요?"를 묻는다: **다음 결제부터**(기본) / 처음부터.
- 다음 결제부터: `price_change`에 (다음 결제일, 새 금액)을 추가한다. 지난 결제 · 누적 지출은 그대로.
- 처음부터: 가격 변경 기록을 모두 지우고 기본 금액을 바꾼다.
- 그 날짜의 가격 = `effective_from`이 그 날짜 이하인 가장 최근 변경, 없으면 기본 금액.
- 상세의 결제 이력에서 직전보다 오른 회차에 "인상", 내린 회차에 "인하" 표시.

### 2-6. 일시정지 · 해지

| 동작 | 저장 | 화면 |
|---|---|---|
| 일시정지 | `status = PAUSED` + `pause` 행 추가(시작일 = 오늘, 끝 없음) | 목록 "일시정지" 필터, 합계에서 빠짐 |
| 다시 시작 | `status = ACTIVE` + 열린 `pause` 행의 끝 = 어제 | 다음 결제일은 원래 규칙대로 (기준일을 옮기지 않음) |
| 해지 | `status = CANCELLED` + `cancelled_on`(기본 오늘, 날짜 변경 가능) | 목록 "해지" 필터, 아낀 돈 계산에 사용 |
| 해지 취소 | `status = ACTIVE`, `cancelled_on = null` | – |
| 삭제 | soft delete (`deleted_at`) | 어디에도 보이지 않고 아낀 돈에서도 빠짐. "잘못 등록한 것"을 지우는 용도라고 안내 |

해지 버튼은 "해지하러 가기"(해지 주소가 있으면 브라우저로 열고 돌아오면 "해지했나요?" 확인)와 "해지로 표시"를 함께 둡니다. 실제 해지는 앱이 대신하지 않습니다.

### 2-7. 무료체험

| 항목 | 규칙 |
|---|---|
| 저장 | `trial_started_on`이 있으면 체험 구독. 체험 종료일 = 첫 결제일 |
| 진행 막대 | (오늘 − 시작일) ÷ (첫 결제일 − 시작일) |
| 합계 | 결과를 고르기 전(`trial_outcome = PENDING`)에는 홈 · 통계 합계에 넣지 않는다. 캘린더에는 "체험 종료" 마커로만 |
| 결과 | "계속 쓸래요" → `KEPT`, 일반 구독으로 합계에 들어감. "해지했어요" → `CANCELLED` + `cancelled_on` = 오늘(첫 결제일 이후면 그 날짜 선택). 첫 결제일이 지나도(다음 날부터. 당일까지는 합계에서 제외) 고르지 않으면 `KEPT`로 간주하고 홈에 "결제됐나요?" 카드 |
| 알림 | 첫 결제일 2일 전 · 1일 전 · 당일 (2-12) |

### 2-8. 기간 집계

| 값 | 정의 |
|---|---|
| 이번 달 기간 | [이번 달의 시작일, 다음 달의 시작일). 시작일은 설정 "월 시작 기준일"(1~28, 기본 1). 예: 25일이면 10월 기간 = 10/25 ~ 11/24. 기간 이름은 시작일이 속한 달 |
| 이번 달 구독료 | 이번 달 기간 안에 2-3 규칙으로 생기는 결제의 합 (체험 PENDING 제외) |
| 월 평균 | 이용 중 구독 각각의 "한 달 환산액" 합. 환산 = 매월 금액 / 매년 ÷ 12 / 매주 × 52 ÷ 12 / 직접은 주기를 월로 바꿔 나눔 (일 단위는 1년 365일 기준). 구독별로 원 단위 반올림한 뒤 더한다 |
| 연간 환산 | 월 평균 × 12 |
| 지난달 대비 | 이번 달 구독료 − 지난달 구독료 (같은 규칙) |
| 누적 지출 | 첫 결제일부터 오늘까지(오늘 포함) 생긴 결제의 합 |

### 2-9. 아낀 돈 · 해지 고민 · 중복

| 값 | 정의 |
|---|---|
| 아낀 돈 (구독 하나) | 해지하지 않았다면 해지일부터 오늘까지 생겼을 결제의 합. 체험 중 해지는 첫 결제일부터 셈. 일시정지 기간은 빼고 가격 변경은 반영 |
| 지금까지 아낀 돈 | 해지한 구독 전체의 합 (삭제한 것 제외) |
| 해지 고민함 | 사용자가 표시한 구독(`consider_cancel`). "해지하면 연 X원" = 대상 구독의 연간 환산 합 |
| 중복 | 이용 중 구독 중 같은 카테고리가 2개 이상인 영상 · 음악 · 클라우드 · AI. 쇼핑 · 생활 · 기타는 중복으로 보지 않음 |
| 연간 결제 비교 | 프리셋에 같은 서비스의 연간 요금제가 있을 때만: (월 금액 × 12) − 연간 금액. 매월 결제 구독만, 요금제 이름이 같은 연간 요금제를 먼저 고르고 없으면 연간 요금제가 하나뿐일 때만 비교. 0원 이하는 숨김 |

### 2-10. 프리셋

- 앱에 들어 있는 JSON(`core/data/src/main/assets/presets/services_ko.json`, `version` 포함). 서버에서 받지 않는다.
- 항목: `id`, `name`, `category`, `colorKey`, `plans[]`(이름 · 금액 · 통화 · 주기), `cancelUrl`(선택).
- 요금은 **출시 · 업데이트마다 공식 요금표로 확인**하고, 화면에 "기본 요금은 {yyyy.MM} 기준이에요, 실제와 다르면 수정하세요"를 보여준다.
- 1차 프리셋 30개 안팎: 영상(넷플릭스, 유튜브 프리미엄, 티빙, 쿠팡플레이, 웨이브, 디즈니+, 왓챠), 음악(멜론, 지니, 스포티파이, 유튜브 뮤직, 플로, 애플 뮤직), 쇼핑 · 생활(쿠팡 와우, 네이버플러스 멤버십, 배민클럽, 컬리멤버스), 클라우드(구글 원, iCloud+, 네이버 MYBOX), AI · 생산성(ChatGPT Plus, Claude Pro, Notion, Microsoft 365), 독서(밀리의 서재, 리디셀렉트), 게임(닌텐도 스위치 온라인, PlayStation Plus).

### 2-11. 카테고리

| 값 | 표시 |
|---|---|
| `VIDEO` | 영상 |
| `MUSIC` | 음악 |
| `SHOPPING` | 쇼핑 · 생활 |
| `CLOUD` | 클라우드 |
| `AI` | AI · 생산성 |
| `READING` | 독서 |
| `GAME` | 게임 |
| `ETC` | 기타 |

### 2-12. D-day · 알림 대상

| 항목 | 규칙 |
|---|---|
| D-day | 다음 결제일까지 남은 날. 당일 "오늘", 내일 "내일", 그 외 `D-n` |
| 강조 | 오늘 ~ 3일 이내는 `danger` |
| 결제 알림 | 다음 결제일이 (오늘 + N일)이면 보낸다. N = 구독별 설정(끔 · 당일 · 1일 전 · 3일 전 · 7일 전), 기본은 전역 설정(1일 전). 매년 결제는 기본 7일 전 |
| 체험 알림 | 2-7. 결제 알림과 같은 날이면 체험 알림 하나만. 체험 알림을 만들기 전(1차)에는 체험 중 구독의 첫 결제일도 일반 결제 알림으로 보낸다 |
| 여러 건 | 구독마다 알림 하나. 두 건 이상이면 "다가오는 결제 n건" 묶음 요약을 함께 보낸다. 알림을 누르면 그 구독 상세(뒤로 가면 홈), 요약을 누르면 앱 |
| 발송 시각 | 알림 설정의 시각(오전 8시 ~ 오후 9시, 기본 오전 9시). WorkManager 하루 1회 작업이라 몇 분 늦을 수 있음. 정확한 알람 권한을 요청하지 않는다. 같은 날 작업이 두 번 돌아도(알림 시각 변경 등) 한 번만 보낸다 |

## 3. 화면 구조

### 3-1. 내비게이션

하단 탭 5개: **홈 / 목록 / 캘린더 / 통계 / 더보기**. 탭마다 백스택을 따로 둡니다.

```
온보딩 (첫 실행 1회) ─→ 홈

메인 탭
 ├─ 홈 ──────┬─ 구독 상세 ─┬─ 구독 수정
 │           │             ├─ 파티 정산 (3차)
 │           │             └─ 사용 체크 (3차, 상세 안 카드)
 │           ├─ + ─ 서비스 선택 ─ 구독 입력
 │           └─ 무료체험 카드 ─ 무료체험 (2차)
 ├─ 목록 ────┬─ 구독 상세
 │           └─ + ─ 서비스 선택 ─ 구독 입력
 ├─ 캘린더 ──┬─ 날짜 선택 → 바텀시트(그날 결제)
 │           └─ 구독 상세
 ├─ 통계 ────┬─ 아낀 돈 · 해지 고민 (2차)
 │           ├─ 가성비 분석 (3차)
 │           └─ 카테고리 → 목록(필터 적용)
 └─ 더보기 ──┬─ 무료체험, 파티 관리, 연말 리포트
             ├─ 알림 설정, 위젯 설정
             ├─ 백업 내보내기 · 불러오기, 광고 제거
             └─ 약관 및 정책, 다른 앱 둘러보기, 문의하기
```

## 4. 주요 화면 동작

### 4-1. 홈

순서: 이번 달 카드 → 체험 경고(있을 때) → 다가오는 결제 → 카테고리 칩

| 영역 | 내용 |
|---|---|
| 이번 달 카드 | "{M}월 구독료" + 금액(2-8) + "지난달보다 ±n원" + "월 평균 n원 · 연간 n만 원"(만 원 단위 반올림, 1만 원 미만은 원 단위). 월 시작 기준일이 1이 아니면 기간을 작게 표시 ("10.25 ~ 11.24") |
| 체험 경고 | 체험 종료가 3일 이내인 구독이 있으면 "무료체험 n건 종료 임박" 카드 → 무료체험 화면. 2차 |
| 결제됐나요? | 체험 종료일이 지났는데 결과를 고르지 않은 구독. "계속 쓸래요 / 해지했어요" 바로 선택. 2차 (무료체험 화면과 함께) |
| 다가오는 결제 | 구독별 다음 결제 중 오늘 포함 가까운 3개(날짜 → 이름 순). 행: 아이콘 · 이름 · "M월 d일 · D-n" · 금액. "전체보기"는 캘린더 탭으로 |
| 카테고리 칩 | 이용 중 구독(목록의 "이용 중" 필터와 같은 기준)의 카테고리별 개수. 누르면 목록 탭(해당 카테고리 필터) |
| FAB | 서비스 선택 |
| 빈 상태 | "구독을 등록해 보세요" + 빠른 등록 칩(넷플릭스 · 유튜브 프리미엄 · 쿠팡 와우 · 직접 입력) |

### 4-2. 목록

| 항목 | 정한 내용 |
|---|---|
| 상태 필터 | 이용 중(기본) · 일시정지 · 해지 · 체험 중. 개수 표시, 0이면 칩 숨김(이용 중 제외). 체험 중 = 결과를 고르기 전(2-7, 첫 결제일 당일까지)인 이용 중 구독이고, 이용 중에서는 빠진다 |
| 정렬 | 결제일순(기본, 다음 결제일) · 금액순(월 환산, 큰 순) · 이름순. DataStore에 기억 |
| 묶음 | 카테고리 헤더로 묶음. 금액순 · 이름순에서는 묶지 않음 |
| 행 | 아이콘 · 이름(요금제) · "매월 14일 · 파티 4인" · 금액. 매년 · 직접 주기는 금액 아래 "/월 n원" |
| 합계 | 상단에 현재 필터의 월 환산 합 |
| 카테고리 필터 | 통계 · 홈에서 들어오면 칩으로 표시, ✕로 해제 |

### 4-3. 서비스 선택 · 구독 입력

- 서비스 선택: 검색창 + 카테고리 칩 + 프리셋 목록 + 하단 고정 "목록에 없어요(직접 입력)". 이미 이용 중인(체험 중 포함, 일시정지 · 해지 제외) 서비스에 "등록됨" 표시 (다시 등록은 가능). 검색은 대소문자 · 공백을 무시한 이름 포함 검색.
- 구독 입력 헤더: 취소 / 구독 추가(수정 시 "구독 수정") / 저장.
- 입력: 요금제 칩(프리셋) → 금액 · 통화 → 주기 칩(매월 · 매년 · 매주 · 직접) → 첫 결제일 → 무료체험 토글(켜면 시작일, 첫 결제일 라벨이 "체험 종료일"로) → 결제 수단(자유 입력, 전에 쓴 값 자동 완성) → 카테고리 → 알림 → 아이콘 색 → 해지 주소 → 사용 체크 켜기(3차) → 메모.
- 프리셋으로 들어오면 첫 요금제(키에 `planIndex`가 있으면 그 요금제)를 골라 둔다.
- 무료체험을 켜면 시작일 = 오늘, 체험 종료일(첫 결제일) = 시작일 + 1개월. 시작일이 종료일보다 앞이어야 저장할 수 있다.
- 결제 수단 자동 완성: 입력창 아래에 다른 구독에서 쓴 값을 칩으로 보여주고, 입력한 글자가 들어 있는 것만 남긴다. 기본값은 설정의 기본 결제 수단.
- 직접 주기는 단위(일 · 주 · 개월 · 년) + 간격 2~99.
- 첫 결제일 기본값: 오늘. 과거 날짜를 고르면 "지금까지 n회 결제" 미리 보여줌.
- 수정에서 금액을 바꾸면 2-5 시트.
- 저장 조건: 이름 1~30자, 금액 > 0. 아니면 저장 버튼 비활성.
- 수정 화면 맨 아래 "삭제" → 확인 다이얼로그(2-6 안내).

### 4-4. 구독 상세

| 영역 | 내용 |
|---|---|
| 헤더 | 뒤로 · 수정 |
| 위쪽 | 아이콘 · 이름 · "요금제 · 주기 · 결제 수단" · 상태 뱃지 |
| 통계 카드 2개 | 금액(주기) · 지금까지(누적 지출) |
| 다음 결제 | "M월 d일 · D-n" (해지 · 일시정지면 숨김) |
| 사용 체크 (3차) | 사용 체크를 켠 구독만. "이번 달 n번 썼어요 · 1회당 n원" + "+1" 버튼 (오늘 날짜로 기록, 길게 누르면 날짜 선택) |
| 파티 (3차) | 파티 멤버가 있으면 "파티 n인 · 내 몫 n원" → 파티 정산 |
| 결제 이력 | 최근 12회, 최신순. 인상 · 인하 · 일시정지 구간 표시. "더보기"로 전체. 결과를 고르기 전인 체험은 비어 있다. 규칙은 `core:domain` `paymentHistory` |
| 메모 | 있을 때만 |
| 하단 버튼 | 이용 중: 일시정지 · 해지하러 가기 / 일시정지: 다시 시작 · 해지 / 해지: 해지 취소 |
| 해지 시트 | "해지하러 가기"는 이용 중이고 해지 주소가 있으면 브라우저로 열고, 앱으로 돌아오면 "해지했나요?" 시트. 주소가 없거나 일시정지 상태의 "해지"는 바로 시트. 해지일은 기본 오늘, 오늘까지만 고른다 |
| 해지 고민 (2차) | 헤더 메뉴 "해지 고민함에 담기 / 빼기" |

### 4-5. 캘린더

| 항목 | 정한 내용 |
|---|---|
| 헤더 | "yyyy년 M월" + 이전 · 다음, "이번 달 n건 · n원" (월 시작 기준일과 무관하게 달력 월 기준, 결과를 고르기 전인 체험 제외. 규칙은 `core:domain` `periodPayments`) |
| 그리드 | 일요일 시작 5~6주. 결제가 있는 날은 서비스 아이콘 최대 2개 + "+n". 체험 종료일은 점선 원 마커. 오늘 primary 원, 선택한 날 primary-soft 원 |
| 날짜 선택 | 바텀시트: "M월 d일 (요일) · n원" + 그날 결제 목록 → 상세. 결제가 없으면(체험 종료일만 있는 날 포함) 시트 대신 아무 일도 없음. 달을 바꾸면 선택을 지운다 |
| 범위 | 앞으로 12개월, 지난 24개월까지 이동 |

### 4-6. 통계 (2차)

| 영역 | 내용 |
|---|---|
| 기준 | 내 부담액 기준 (파티 구독은 내 몫). 화면 위 안내 "파티 구독은 내 몫만 계산해요". 파티(3차) 전까지는 전체 금액이고 안내도 숨긴다 |
| 카테고리 비중 | 이번 달 월 환산 기준 도넛 + 범례(이름 · 정수 % , 합 100). 큰 순, 기타는 회색. 가운데 "구독 n개". 항목을 누르면 목록 탭(카테고리 필터) |
| 12개월 | 최근 12개 "이번 달 기간"의 실제 결제 합 막대. 이번 달 강조 + 이번 달 금액 · 지난달 대비 |
| 연간 환산 | "지금처럼 유지하면 1년에 n원" |
| 카드 2개 | 해지 고민함 n개 → 아낀 돈 화면(해지 고민 탭) / 지금까지 아낀 돈 → 아낀 돈 화면(기록 탭) |
| 광고 | 화면 맨 아래 인라인 배너 (`ads-strategy.md`) |

### 4-7. 무료체험 (2차)

- 진행 중: 종료 가까운 순. 카드에 "M월 d일 자동결제 n원", D-day, 진행 막대, "해지했어요 / 계속 쓸래요". 종료 1일 이내는 `danger` 테두리.
- 지난 체험: 결과 칩("해지함 · n원 아낌", "구독 전환"), 최근 90일.
- + 버튼: 구독 입력을 무료체험 토글을 켠 상태로 연다.

### 4-8. 아낀 돈 · 해지 고민 (2차)

| 탭 | 내용 |
|---|---|
| 해지 고민함 | 상단 "아래 n개를 해지하면 연 n원 아껴요" + 목록(이번 달 사용 n회 또는 "중복"이 이유로 보임. 사용 체크(3차) 전에는 중복이 아니면 월 환산) + 각 "해지하러 가기"(해지 주소가 있으면 브라우저, 없으면 상세). 중복 카드(2-9). 연간 결제 비교 카드(해당 있을 때) |
| 아낀 돈 | 상단 "지금까지 n원 아꼈어요" + 해지한 구독별 아낀 돈(큰 순) |

### 4-9. 파티 정산 (3차)

- 멤버: 이름(1~10자)만. 나는 항상 포함되어 있고 지울 수 없음. 최대 9명 추가.
- 분담: 균등(기본, 총액 ÷ 인원, 원 단위 내림, 남는 원은 나에게) 또는 멤버별 금액 직접 입력. 내 몫 = 총액 − 다른 멤버 몫 합.
- 정산: 결제가 있는 달(이번 달 기간)마다 멤버별 "받음" 체크. 지난 정산은 3개월까지 보여줌.
- 요청 문구: "{이름}아/야 이번 달 {서비스} {금액}원 보내줘!" — 받침 유무로 "아/야" 선택. 공유 인텐트(`ACTION_SEND`)로 보내고 앱은 어디로 보냈는지 모른다. 카카오 SDK를 쓰지 않는다.
- 정산 알림: 결제일 다음 날 미정산 멤버가 있으면 1회 (알림 설정에서 끌 수 있음).

### 4-10. 가성비 분석 (3차)

- 대상: 사용 체크를 켠 이용 중 구독.
- 1회당 비용 = 이번 달 내 부담액(월 환산) ÷ 이번 달 사용 횟수, 원 단위 반올림. 0회는 "사용 안 함"(`danger`).
- 정렬: 사용 안 함 → 1회당 비용 큰 순. 막대 길이는 목록 안 최대값 대비.
- 사용 안 함 구독에 "해지 고민함에 담을까요?" 카드.

### 4-11. 연말 리포트 (3차)

- 12월 1일 ~ 1월 31일에 홈에 배너, 더보기에서는 항상 지난해 · 올해 리포트.
- 카드 4장(스와이프): 올해 총 지출 · 카테고리 1위 · 가장 오래 쓴 구독 · 올해 아낀 돈.
- "이미지로 공유": 카드를 1080×1920 비트맵으로 그려 공유 인텐트. 앱 이름 표시. 저장 권한 없이 캐시 폴더 + FileProvider.

## 5. 온보딩

첫 실행에 한 번. 로그인 · 약관 동의 화면은 없습니다 (서버로 받는 개인정보가 없음. 개인정보 처리방침은 더보기와 스토어에 게시).

1. 서비스 다중 선택(01): 요금제가 있는 프리셋 그리드(검색 · 카테고리 칩), 선택하면 "n개 선택 · 월 n원"(월 환산 합). "n개 등록하고 시작하기"는 각 서비스의 첫 요금제 · 그 요금제의 주기 · 첫 결제일 = 오늘로 한꺼번에 저장하고, 홈에 "결제일을 확인해 주세요" 안내 카드(누르면 목록, 누르거나 닫으면 다시 보이지 않음). 요금제가 없는 프리셋은 금액을 몰라 온보딩에서 숨기고, 서비스 선택에서 직접 금액을 넣어 등록한다.
2. "건너뛰기"는 바로 홈(빈 상태).
3. 알림 권한은 온보딩에서 묻지 않고, 구독을 새로 저장할 때 권한이 없으면 묻는다 (Android 13 이상, 수정 저장 · 온보딩 일괄 등록에서는 묻지 않음). 거절해도 저장은 된다. 두 번 거절하면 시스템이 더 묻지 않으므로 알림 설정의 기기 알림 카드로 켜도록 안내한다.
4. 맞춤 광고 동의(UMP)는 광고를 처음 띄울 때 확인한다 (`ads-strategy.md`).

## 6. 설정 구조 (더보기 탭)

```
더보기 (탭)
├─ 관리
│   ├─ 무료체험 ─────────→ 4-7 (2차)
│   ├─ 파티 관리 ────────→ 파티가 있는 구독 목록 → 파티 정산 (3차)
│   └─ 연말 리포트 ──────→ 4-11 (3차)
├─ 설정
│   ├─ 알림 ─────────────→ 알림 설정 (아래)
│   ├─ 위젯 ─────────────→ 위젯 설정 (2차)
│   ├─ 월 시작 기준일 ───→ 1~28 선택 시트 (월급일)
│   ├─ 달러 환율 ────────→ 숫자 입력 시트 (1달러 = n원, 0보다 큰 정수)
│   ├─ 기본 결제 수단 ───→ 새 구독에 미리 채울 값 (입력 시트, 비우고 저장하면 지움)
│   └─ 화면 모드 ────────→ 라이트 / 다크 / 시스템
├─ 데이터
│   ├─ 백업 내보내기 ────→ 시스템 파일 저장(SAF), `subcal-backup-yyyyMMdd.json`
│   └─ 백업 불러오기 ────→ 파일 선택 → 미리보기(구독 n개) → "지금 데이터를 바꿀까요?" → 덮어쓰기
├─ 지원
│   ├─ 광고 제거 ────────→ 1회 구매 (`ads-strategy.md`) (출시 단계)
│   ├─ 앱 평가하기 (출시 단계)
│   ├─ 문의하기 (출시 단계) ─→ 메일 앱 (앱 버전 · 기기 정보만 본문에)
│   └─ 다른 앱 둘러보기 (출시 단계) ─→ 개발자의 다른 앱 소개 페이지 (웹뷰, 데이즈와 같은 페이지 · `from=jpark.bro.subcal`)
├─ 정보
│   ├─ 약관 및 정책 (출시 단계) → 개인정보 처리방침(굵게, 맨 위) · 오픈소스 라이선스 · Pretendard 글꼴 라이선스
│   └─ 앱 버전
└─ 모든 데이터 삭제 ─────→ 확인 문구 입력("삭제") 후 Room(위젯 설정 포함) · DataStore 초기화, 떠 있는 알림 지우기, 온보딩으로
```

- 알림 설정: 기기 알림 상태 카드(꺼져 있으면 시스템 설정 열기) · 결제 알림 토글 · 기본 알림 시점(당일 · 1일 전 · 3일 전 · 7일 전) · 무료체험 알림 · 파티 정산 알림(3차) · 월초 요약(이번 달 기간 첫날, 2차) · 알림 시각(오전 8시 ~ 오후 9시 정각 중 선택) · 구독별 설정 목록(해지한 구독 제외, 이름순, 기본 · 끔 · 당일 · 1 · 3 · 7일 전). 결제 알림을 끄면 시점 · 시각 · 구독별 설정을 숨긴다.
- 아직 만들지 않은 단계(2 · 3차, 출시 단계)의 메뉴는 숨긴다 (비활성 표시하지 않음).
- 앱 잠금 · 백업 자동 내보내기 · 클라우드 백업은 범위 밖.

## 7. 위젯 (2차)

- 크기: 작게(2×2) · 중간(4×2).
- 작게: 가장 가까운 결제 1건 — 아이콘 · 이름 · D-day · 금액. 결제가 없으면 "다가오는 결제가 없어요".
- 중간: "{M}월 구독료 n원" + 다가오는 결제 2건.
- 배경: 테마(기기 다크 모드를 따름) · 다크 · 화이트. 위젯 설정에서 고름.
- 탭: 작게는 그 구독 상세, 중간은 홈.
- 갱신: 구독 · 설정 변경 시, 매일 자정, 기기 시각 · 시간대 변경 시.
- 세부 구현은 `widget/CLAUDE.md`.

## 10. 출시 범위

1 · 2 · 3차는 **개인용으로 먼저 쓰면서 만드는 기능 단계**다. 데이터는 Room · DataStore에만 두고 외부 설정이 필요한 기능을 넣지 않는다. 외부 계정 · 콘솔 설정이 필요한 작업은 모두 "출시 단계"로 미뤄 마지막에 한다 (`module-map.md` 9장).

| 구분 | 포함 |
|---|---|
| 1차 (MVP) | 온보딩, 홈, 목록, 서비스 선택, 구독 입력 · 수정 · 상세(일시정지 · 해지 · 가격 변경), 캘린더, 결제 알림 · 알림 설정, 더보기(설정 · 백업), 다크 모드 |
| 2차 | 통계, 무료체험, 아낀 돈 · 해지 고민, 위젯, 월초 요약 알림 |
| 3차 | 파티 정산, 사용 체크 · 가성비 분석, 연말 리포트 |
| 출시 단계 (최후순위) | 광고 · 광고 제거, Firebase(오류 수집 · 사용 분석 · 원격 설정), 개인정보 처리방침 페이지, 앱 평가하기 · 문의하기 · 다른 앱 둘러보기, 오픈소스 라이선스, 스토어 등록 |
| 범위 밖 | 은행 · 카드 · 문자 연동 자동 등록, 로그인 · 클라우드 동기화, 가족 간 데이터 공유, 자동 환율, 앱 잠금, 브랜드 로고 이미지, 결제 대행 · 해지 대행 |
